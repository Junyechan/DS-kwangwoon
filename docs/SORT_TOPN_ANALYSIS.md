담당: 정렬(`src/sort.*`), Top-N 추천(`src/recommendation.*`)

## 1. 한눈에 보기

| 기능 | 함수 | 자료구조 / 알고리즘 | 시간 | 추가 공간 | Stable |
|---|---|---|---|---|---|
| 1시간 요금 낮은 순 | `sortByFee(list)` | Linked List Merge Sort | Θ(n log n) | O(log n) (재귀) | O |

## 3. Merge Sort (연결 리스트)

### 동작

1. **분할** `splitHalf`: slow(1칸) / fast(2칸) 포인터로 중간 노드를 찾아 리스트를 둘로 끊는다.
2. **정복** 양쪽을 재귀로 정렬한다. 노드가 0~1개면 이미 정렬된 상태.
3. **병합** `merge`: 두 리스트의 머리끼리 비교해 작은 쪽 노드를 `next`로 이어 붙인다. 데이터 복사나 새 노드 할당 없이 포인터만 바꾼다.
4. 정렬이 끝나면 마지막 노드를 찾아 `tail`을 갱신한다 (O(n), 한 번).

### 왜 연결 리스트에 Merge Sort인가

- Quick Sort, Heap Sort는 `a[i]`처럼 임의 위치에 바로 접근해야 효율이 나온다. 연결 리스트는 i번째 노드까지 O(i)가 걸린다.
- Merge Sort는 앞에서부터 순서대로만 읽으므로 연결 리스트와 잘 맞는다.
- 배열 Merge Sort는 병합용 O(n) 임시 배열이 필요하지만, 연결 리스트는 `next`만 바꾸면 되어 추가 메모리가 재귀 스택뿐이다.
- 최악의 경우에도 O(n log n)이라 입력 순서에 따라 느려지지 않는다 (Quick Sort는 최악 O(n²)).

### 시간 복잡도

한 단계에서 하는 일: 분할(중간 찾기) cn/2, 병합 최대 n−1번 비교.

```
T(n) = 2T(n/2) + Θ(n),  T(1) = Θ(1)
```

재귀 트리의 높이가 log₂ n이고 각 층의 일이 Θ(n)이므로 **T(n) = Θ(n log n)** (최선·평균·최악 모두).
Master Theorem으로도 a = 2, b = 2, f(n) = Θ(n) = Θ(n^(log₂2)) → 2번 경우 → Θ(n log n).

비교 횟수만 세면:

- 최악: n⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1 ≤ n log₂ n
- 최선(이미 정렬 / 역순): 병합마다 한쪽이 먼저 바닥나서 약 (n/2) log₂ n

### 공간 복잡도

- 병합: 더미 노드 1개 → O(1)
- 재귀 깊이: log₂ n → **O(log n)** (842곳이면 약 10단계)

### Stable 정렬

`merge`는 비교 함수가 `true`(같음 포함)이면 **왼쪽 리스트** 노드를 먼저 붙인다. 비교 함수가 `<=`, `>=`로 같은 값에 `true`를 돌려주므로, 값이 같은 두 주차장은 원래 순서를 유지한다.
그래서 "주차면수 순 → 요금 순"처럼 연속으로 정렬하면, 요금이 같은 주차장끼리는 주차면수 순서가 남는다.

### 요금 정보 없음 처리

원본 CSV에는 "유료"인데 요금이 비어 1시간 요금이 0원으로 계산되는 주차장이 8곳 있다. 0원으로 두면 요금순 1등으로 보이므로 로더가 `hourlyFee`를 `FEE_UNKNOWN(-1)`로 표시하고, `feeAscending`은 이 값을 요금과 상관없이 맨 뒤로 보낸다. 무료 주차장(유무료구분 "무료", 15곳)은 0원 그대로 맨 앞에 온다.

## 4. Top-N 추천 (Heap)

### 아이디어

N개만 필요하면 m개를 전부 정렬할 필요가 없다. **크기를 N으로 유지하는 Max Heap**을 쓰면 루트에는 "지금까지 고른 N개 중 가장 비싼 주차장"이 있다.

1. 후보를 처음부터 한 번 훑는다.
2. Heap이 N개 미만이면 넣는다 (`heapPush`, sift-up).
3. 꽉 찼으면 새 후보를 루트와 비교한다. 루트보다 싸면 루트를 새 후보로 바꾸고 sift-down, 아니면 버린다.
4. 다 훑은 뒤 Heap Sort처럼 루트를 꺼내 배열 뒤에서부터 채우면 배열이 싼 순서로 정렬된다.

Min Heap에 m개를 다 넣고 N번 꺼내도 되지만 공간이 O(m) 필요하다. Max Heap 방식은 O(N)만 쓴다.

### 동점 처리 (정렬과 결과 일치)

Heap Sort는 원래 Stable하지 않다. 그래서 각 원소에 후보 리스트에서의 위치 `order`를 함께 넣고,
"요금이 낮을수록, 요금이 같으면 `order`가 작을수록 앞" 이라는 순서(`ranksBefore`)로만 비교한다.
같은 원소가 없는 완전한 순서이므로 결과가 항상 하나로 정해지고, **`sortByFee` 결과의 앞 N개와 똑같다.**
테스트에서 실제 842곳에 대해 N = 1, 5, 10, 50, 842 모두 이를 확인한다.

### 시간 복잡도

| 단계 | 횟수 | 1회 비용 | 합계 |
|---|---|---|---|
| 처음 N개 push | N | O(log N) | O(N log N) |
| 나머지 m − N개와 루트 비교 | m − N | O(1) | O(m) |
| 루트 교체 + sift-down | 최대 m − N | O(log N) | O(m log N) |
| 마무리 Heap Sort (N번 pop) | N | O(log N) | O(N log N) |

**최악 O(m log N)** (요금이 점점 싸지는 순서로 들어와 매번 교체되는 경우).
무작위 순서에서는 i번째 후보가 교체될 확률이 N/i라서 교체 횟수 기댓값이 약 N ln(m/N)뿐이고, 비교 횟수는 거의 m에 가깝다.

전체 정렬 후 앞 N개를 자르는 방법은 O(m log m)이다. N이 작을수록(보통 3~10) Heap 쪽이 유리하고, N = m이면 둘 다 O(m log m)이다.

### 공간 복잡도

Heap 배열 N칸 → **O(N)**. 노드 데이터는 복사하지 않고 포인터만 담는다 (결과 리스트에 담을 때만 복사).

비교 횟수는 비교 함수 호출을 센 값, 시간은 `-O2` 빌드 기준. Top-N은 N = 10.

| 무작위 | 1,000 | 8,709 | 9,965 | 0.87 | 0.14 | 1,199 | 0.01 |
| 무작위 | 4,000 | 42,695 | 47,863 | 0.89 | 0.60 | 4,185 | 0.06 |
| 무작위 | 16,000 | 202,255 | 223,452 | 0.91 | 4.33 | 16,195 | 0.21 |

| 무작위 | 256,000 | 4,251,176 | 4,599,240 | 0.92 | 229.48 | 256,142 | 8.96 |

| 역순(최악 Heap) | 256,000 | 2,286,592 | 4,599,240 | 0.50 | 101.48 | 1,553,043 | 11.83 |

읽는 법:

- 정렬 비교 횟수 / (n log₂ n) 비율이 n이 256배 커져도 0.86~0.92로 거의 일정 → **Θ(n log n)** 이 맞다.
- 역순 입력은 병합 때 한쪽이 먼저 끝나서 비율이 0.5 → 최선의 경우 (n/2) log₂ n과 일치.
- 무작위 입력에서 Heap 비교는 거의 m (n + 약 200) → 교체가 드물다는 분석과 일치.
- 역순(최악)에서 Heap 비교는 약 6m. 후보마다 루트 비교 1번 + sift-down 최대 2⌊log₂ 10⌋ = 6번이라 7m 이하 → **O(m log N)**. 그래도 같은 데이터 전체 정렬보다 빠르다.
- 실행 시간은 메모리 캐시 영향으로 n이 커지면 이론보다 조금 더 늘어난다 (연결 리스트는 노드가 메모리 여기저기 흩어져 있다).
